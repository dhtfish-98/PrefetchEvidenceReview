# Defensive scope

The complete selected mechanism is offline Prefetch record evidence extraction with structural review. The product reads an explicitly selected regular file or exact immutable bytes. It never scans a live Prefetch directory, downloads evidence, invokes shell commands, decompresses MAM, loads Windows libraries, resolves recorded paths, starts recorded programs or writes evidence back. Separate optional test scripts build and invoke an independent parser on generated inert fixtures; they are not runtime features.

Supported profile: uncompressed v17, v23, v26; SCCA signature; exact recorded file size; 84-byte header; information blocks of 68/156/220 bytes; complete 20/32-byte metric and 12-byte trace arrays; complete filename table; all 40/104-byte volume entries, device strings, reference arrays and directory strings. All declared extents are in bounds and disjoint. String references must point to exact table starts and match recorded UTF-16 lengths. Every trace next-index is checked, all trace cycles are rejected, and metric chains must have their declared length, distinct ownership and cover all declared traces. This is a conservative documented profile; unfamiliar sharing, orphan trace arrangements and encodings return OPEN rather than being repaired or treated as safe.

Volume file-reference headers are version 1 with eight bytes for v17 and version 3 with sixteen bytes for v23/v26. Their declared sizes must match their counts. Modern eight-byte unknown prefixes remain hashed. NTFS entry/sequence interpretation uses the complete low 48/high 16 bits, but does not authenticate an actual filesystem record. Metric references are independently interpreted and source-positioned.

Strict UTF-16LE decoding supports BMP and paired astral characters. Unpaired surrogates, embedded NUL, empty mandatory strings, missing terminators, noncanonical device-path lengths and interior empty filename-table entries return OPEN. Executable padding after its first NUL and unknown information/volume fields are retained as digests, without interpreting them as trustworthy content. Documented directory counts exclude their trailing NUL; this profile requires the NUL. Unicode strings are never normalized into filesystem paths.

FILETIME is unsigned integer 100 ns evidence. Zero means UNSET; v26 preserves all eight slots, including gaps and all-zero records. Supported nonzero times retain the seventh fractional decimal digit. Values beyond the Python UTC datetime range return OPEN. Counters and timestamps remain unauthenticated and do not prove chronology or execution on this or any other host. Stored Prefetch hashes are numeric declarations, not a recalculated execution-path identity.

MAM variants, XPRESS, v30/v31, other formats, live acquisition, forensic authenticity, behavioral attribution and whole upstream platform behavior are outside the implemented scope and remain OPEN. No claim is made that a model's safeguards will never be triggered or that CVP will approve this work. AI assistance is explicit; human contribution and application requirements require separate assessment.
